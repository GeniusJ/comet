# Dashboard 日志 AI 分析

在 **Kubernetes → 状态与容器日志** 或 **流水线日志** 中读取日志后，点击日志工具栏的 **AI 分析**。
输入问题并点击 **开始分析**，也可按 Ctrl+Enter（macOS 支持 Cmd+Enter）。例如：

- 找出数据库连接超时，列出相关日志和前后上下文。
- 总结这次构建失败的直接证据，区分已知事实和可能原因。
- 根据这些日志，下一步需要核查哪些配置？

结果显示在日志旁，窄屏时显示在日志下方。回答会请求引用 `L1`、`L2` 等快照行号和相关原文；
AI 的推测仍需结合实际环境核查。原有文本搜索与自动换行选项可继续使用。

## 快照和追问

打开面板时固定当前已加载的日志快照，提问后才调用模型。自动刷新或手动刷新日志不会替换这份快照，
因此连续追问使用同一份日志。点击 **使用最新日志并开始新对话** 会清空旧对话并切换到当前日志。
切换工程、环境、Pod、容器或流水线运行节点时，不复用旧来源的分析。

点击 **停止分析**、关闭面板或离开当前日志来源会取消请求，并结束对应 CLI 子进程。
对话仅保存在当前打开的面板中；后续提问携带最近的有限对话内容，长历史会裁剪。

## 本机依赖

运行 Dashboard 的电脑需要安装并登录 Codex CLI。可先在终端检查：

```bash
codex --version
codex exec --help
```

已用 `codex-cli 0.144.5` 验证。集成依赖 `exec --json`、`--ephemeral`、`--sandbox read-only`、
`mcp list --json` 和当前工具开关；旧版本缺少这些能力时应升级 CLI。
认证、模型和模型服务配置沿用本机 Codex CLI，Dashboard 不另存 API Key，也不自动更改这些配置。

## 分析范围

第一版仅分析已加载日志，不检索历史日志库、不读取绑定仓库代码，也不调用 KE 发布或修复代码。
每次调用在独立临时目录中以只读模式运行，通过 stdin 传入日志，使用临时会话，
并禁用 Shell、MCP、插件、Hook、浏览器和多 Agent 等工具能力。
MCP 服务名目前须仅包含英文字母、数字、横线或下划线，确保能够逐个禁用；无法禁用时不启动分析。

提问时会将快照和必要的对话内容提交给 CLI 配置的模型服务。服务端会遮蔽常见的 token、password、
API Key 和 Authorization 字段；这不等于完整的敏感信息识别，业务日志仍应按实际需要选择使用。

单份快照最多 128 KiB，单次分析最长 120 秒（配置探测另限 10 秒），结果最多 64 KiB，
同一 Dashboard 最多同时运行两个分析。CLI 原始诊断不发送到浏览器，避免意外带出凭证；
失败时请在本机终端核查安装、登录、模型服务和版本。结果以 CLI 确认完成为准，连接中断不会标记为成功。
